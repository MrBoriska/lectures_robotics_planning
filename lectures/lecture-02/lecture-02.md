## 1. От непрерывного пространства к графу $G(V, E)$ <span class="badge badge-time">00–15 мин</span>

<div class="grid-3">

<div class="card">
  <h3>1. Регулярные сетки (Grid)</h3>
  <p>Карта делится на регулярные ячейки. Связность:</p>
  <ul>
    <li><strong>4-связность:</strong> ортогональные переходы.</li>
    <li><strong>8-связность:</strong> ортогональные + диагональные.</li>
    <li><em>Проблема:</em> срезание углов (Corner cutting) через тонкие диагонали препятствий.</li>
  </ul>
</div>

<div class="card card-accent">
  <h3>2. Граф видимости (Visibility)</h3>
  <p>Вершины — углы многоугольных препятствий.</p>
  <ul>
    <li>Ребра соединяют вершины с прямой видимостью.</li>
    <li><strong>Свойство:</strong> Гарантирует абсолютно кратчайший евклидов путь в 2D!</li>
    <li><em>Минус:</em> робот притирается вплотную к углам препятствий.</li>
  </ul>
</div>

<div class="card">
  <h3>3. Обобщенная диаграмма Вороного</h3>
  <p>Траектории, равноудаленные от ближайших препятствий.</p>
  <ul>
    <li>Максимальный запас безопасности (Clearance).</li>
    <li>Удобно для навигации в узких коридорах складов и больниц.</li>
    <li>Путь длиннее геометрического оптимума.</li>
  </ul>
</div>

</div>

## 2. Алгоритмы поиска: Дейкстра и $A^*$ <span class="badge badge-time">15–30 мин</span>

<div class="grid-2">

<div class="col">
  <p>Общая схема поиска на графе с очередью с приоритетом (Min-Heap / Open Set):</p>

  <div class="formula-box">
    $$f(n) = g(n) + h(n)$$
  </div>

  <ul>
    <li>$g(n)$ — точная накопленная стоимость пути от старта $s$ до текущей вершины $n$.</li>
    <li>$h(n)$ — эвристическая оценка оставшейся стоимости от $n$ до целевой вершины $g$.</li>
    <li><strong>Дейкстра:</strong> $h(n) \equiv 0 \implies f(n) = g(n)$. Равномерно раскрывает вершины во все стороны круговым фронтом.</li>
  </ul>
</div>

<div class="col">
  <div class="card card-accent">
    <h3>Свойства эвристики $h(n)$:</h3>
    <ul>
      <li><strong>Допустимость (Admissibility):</strong>
        $$h(n) \le h^*(n) \quad \forall n$$
        Эвристика никогда не переоценивает реальную стоимость. <em>Гарантирует глобальную оптимальность найденного пути!</em>
      </li>
      <li><strong>Монотонность / Согласованность (Consistency):</strong>
        $$h(n) \le c(n, n') + h(n')$$
        Удовлетворяет неравенству треугольника. Гарантирует, что при первом извлечении вершины из Open Set ее $g(n)$ уже минимальна (не требуется повторное раскрытие из Closed Set).</li>
    </ul>
  </div>
</div>

</div>

## 3. Выбор метрики эвристики на 2D-сетке <span class="badge badge-time">30–45 мин</span>

<div class="grid-3">

<div class="card">
  <h3>Манхэттенская ($L_1$)</h3>
  $$\Delta x = |x_n - x_g|, \quad \Delta y = |y_n - y_g|$$
  $$h(n) = \Delta x + \Delta y$$
  <ul>
    <li>Допустима строго для <strong>4-связной</strong> сетки.</li>
    <li>Для 8-связной сетки переоценивает путь (недопустима!).</li>
  </ul>
</div>

<div class="card card-accent">
  <h3>Диагональная / Octile</h3>
  $$h(n) = \max(\Delta x, \Delta y) + (\sqrt{2} - 1)\min(\Delta x, \Delta y)$$
  <ul>
    <li>Точная допустимая и монотонная эвристика для <strong>8-связной</strong> сетки при стоимости диагонали $\sqrt{2} \approx 1.414$.</li>
  </ul>
</div>

<div class="card">
  <h3>Евклидова ($L_2$)</h3>
  $$h(n) = \sqrt{\Delta x^2 + \Delta y^2}$$
  <ul>
    <li>Всегда допустима для любого графа.</li>
    <li>Но сильнее недооценивает путь на сетке, чем Octile (раскрывает чуть больше лишних узлов).</li>
  </ul>
</div>

</div>

## 4. Динамическое перепланирование: $D^*$ и $D^*$ Lite <span class="badge badge-time">60–75 мин</span>

<div class="grid-2">

<div class="col">
  <div class="card card-accent">
    <h3>Проблема автономного движения по неполной карте:</h3>
    <ul>
      <li>Робот едет по оптимальному пути, найденному $A^*$.</li>
      <li>Вдруг лидар обнаруживает закрытую дверь или препятствие, блокирующее ребро пути.</li>
      <li><strong>Наивный подход:</strong> перезапустить $A^*$ с нуля. Дорого при частых обновлениях карты!</li>
    </ul>
  </div>

  <div class="card">
    <h3>Концепция $D^*$ Lite (Stentz, Koenig):</h3>
    <p>Поиск ведется <em>от цели к текущему положению робота</em> (обратный поиск). При обнаружении новых препятствий пересчитываются только затронутые стоимости (RHS значения) через инкрементальную очередь с приоритетом.</p>
  </div>
</div>

<div class="col">
  <div class="card card-alert">
    <h3>Сравнение вычислительной сложности в динамике:</h3>
    <table>
      <thead>
        <tr>
          <th>Алгоритм</th>
          <th>Первый запуск</th>
          <th>Перепланирование</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <td><strong>Повторный $A^*$</strong></td>
          <td>$\mathcal{O}(N \log N)$</td>
          <td>$\mathcal{O}(N \log N)$</td>
        </tr>
        <tr>
          <td><strong>$D^*$ Lite</strong></td>
          <td>$\mathcal{O}(N \log N)$</td>
          <td><strong>$\mathcal{O}(k \log k)$</strong>, где $k \ll N$</td>
        </tr>
      </tbody>
    </table>
    <p class="text-sm mt-2">При локальных изменениях карты $D^*$ Lite работает в 10–100 раз быстрее полного перезапуска.</p>
  </div>
</div>

</div>

## 5. Сглаживание траектории (Path Smoothing) <span class="badge badge-time">75–85 мин</span>

<div class="grid-2">

<div class="col">
  <div class="card">
    <h3>Шорткатинг лучами (Raycast Shortcutting):</h3>
    <ol>
      <li>Берем две непоследовательные точки пути $p_i$ и $p_{i+k}$.</li>
      <li>Проверяем отрезок между ними на коллизии с помощью алгоритма Брезенхэма.</li>
      <li>Если коллизий нет — заменяем промежуточную цепочку изломов прямым отрезком.</li>
      <li>Итеративно повторяем до стабилизации длины пути.</li>
    </ol>
  </div>
</div>

<div class="col">
  <div class="card card-success">
    <h3>Градиентная оптимизация пути:</h3>
    <p>Минимизируем функцию гладкости и близости к исходной траектории:</p>
    $$\min_{p_i} \sum_{i=1}^{M-1} \left( \alpha \|p_i - p_i^{orig}\|^2 + \beta \|p_{i-1} - 2p_i + p_{i+1}\|^2 \right)$$
    <ul>
      <li>Первое слагаемое удерживает путь вдали от стен.</li>
      <li>Второе слагаемое минимизирует вторую разность (кривизну).</li>
      <li>Путь становится гладким и пригодным для контроллера колес.</li>
    </ul>
  </div>
</div>

</div>

## Резюме лекции и контрольные вопросы <span class="badge badge-time">85–90 мин</span>

<div class="grid-2">

<div class="card">
  <h3>Главные выводы:</h3>
  <ol>
    <li>Дискретизация на сетку — самый распространенный в ROS метод глобального планирования (Global Planner).</li>
    <li>$A^*$ с монотонной эвристикой дает глобально оптимальный путь на графе за минимальное число раскрытых узлов.</li>
    <li>Для динамических карт алгоритмы семейства $D^*$ обеспечивают быстрое локальное обновление без полного перезапуска.</li>
    <li>Сглаживание (шорткатинг, градиентный спуск) — обязательный этап перед передачей пути контроллеру.</li>
  </ol>
</div>

<div class="card card-accent">

    <li>Как алгоритм Jump Point Search (JPS) ускоряет $A^*$ на открытых пространствах?</li>
